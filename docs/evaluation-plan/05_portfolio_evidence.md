# 05. 포트폴리오 증거 구성 — 실제 결과가 생긴 뒤 채울 틀

> **아직 채울 결과가 없다.** 아래 `[ ]` 칸은 실행 후에만 채운다. 실행 전 계획·추론을 성과로 쓰지 않는다.
> 대상 독자: AI 에이전트 서비스 기획 직무의 채용 담당자·면접관. 이 문서는 그들에게 보일 **구성안**이고, 최종 포트폴리오 문장은 결과가 나온 뒤 쓴다.

## 1. 보여줄 이야기 (한 장 요약 구조)

```
① 내가 정한 기준  →  ② 실제 실패 2건  →  ③ 원인 분리  →  ④ 수정  →  ⑤ 같은 조건 재검증  →  ⑥ 화면 전후 · 한계
```

기능 목록이 아니라 **"이 에이전트는 언제 답하고, 언제 되묻고, 언제 멈추며, 실행 전에 무엇을 확인하는가"를 내가 정하고 검증했다**는 것이 중심이다.

## 2. 섹션별 증거

### ① 기준 — 사용자(장인우)가 정하는 부분

| 넣을 것 | 출처 | 상태 |
|---|---|---|
| 행동 기준표: 답변·되묻기·보류·거절·미리보기·실행 조건 | 02 문서 §2 — ★ 항목 확정본 | [ ] 확정 전 |
| "왜 이 기준인가" 3줄: 세액 단정의 피해, 0원과 미상의 차이, 쓰기는 확인 후 | 사용자 작성 | [ ] |
| 서버가 통제하는 범위 vs 모델이 맡는 범위 그림 | 01 문서 §1 (코드로 확인된 구조) | 사용 가능 |

### ② 실제 실패 2건 — 실행 후 확정

**후보**(정적 열람으로 의심만 된 상태 — 실행으로 재현돼야 쓸 수 있다):

| 후보 | 왜 좋은 사례인가 | 재현 비용 |
|---|---|---|
| **CA-04** 계산 패널 "결정세액 0원" | 답변과 화면이 다른 숫자 — 사용자 신뢰 문제를 바로 보여줌. API 계약과 화면의 경계 | 0 (L1 계약 + L3 고정 응답) |
| **MT-02** 금액 정정이 반영되지 않음 | 멀티턴 상태 설계 — 고객이 고쳤다고 믿는 값과 시스템 값이 다름 | 0 (L1) |
| **FA-03** 모델 장애 중 보이지 않는 미리보기 | 승인 없는 실행 위험 — 에이전트 실행 통제의 핵심 | 0 (L1) |
| RG-03 근거는 맞는데 수치가 틀림 | RAG 의 한계. 단 과거 기록(2026-08-21)이라 **현 HEAD 재현 필요**, 유료 | L2 |

## 3. 지표를 보여줄 때

- 층별로 따로 보인다: L1 통과 n/m · L2 사례별 n회 중 통과 · L3 화면/API 불일치 필드 수. **합산 점수 없음.**
- 분모와 미측정을 같이 적는다. 예: "세액 15건 중 검토 수준 official-doc 이상 0건 → 계산 정확성은 미측정, 독립 계산 일치 15/15".
- 중단 기준(권한 침해·승인 없는 실행)은 평균과 별도 줄로 "0건 / 실행 n회".

## 5. 개인정보

스크린샷·로그·응답 발췌는 합성 계정(`antman` 등)만. 실제 이름·계좌·급여·대화·API 키가 화면이나 터미널에 보이지 않는지 공개 전 확인한다.
