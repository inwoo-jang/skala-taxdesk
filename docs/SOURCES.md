# RAG 자료 수집 목록 — 2026 귀속 기준

> `src/main/resources/tax-docs/` 9종의 본문을 채우기 위한 수집 명세.
> **이 문서의 목적은 "어디서 무엇을 가져와 어떤 형식으로 넣을지"를 고정하는 것**이다.
> 수치는 반드시 원문에서 확인한다 — 기억이나 블로그로 채우면 이 프로젝트가 없애려는 문제를 우리가 만든다.

---

## 0. 먼저 정한 것 — 시점

| 항목 | 값 | 근거 |
|---|---|---|
| 귀속연도 (`effectiveYear`) | **2026** | 증권사 연말 "종합과세 대상 예상 안내"는 당해 귀속분을 안내한다 |
| 상담 시점 | 2026년 하반기 (예상 안내) | 확정 신고 전이므로 "예상"이라는 말이 성립한다 |
| 신고·납부 기한 | **2027-05-31** | 2026 귀속 종합소득세 확정신고 |
| 적용 법령 | **2026년 1월 1일 시행 기준** 소득세법·조특법·국세기본법 | 부칙의 시행일·적용례를 반드시 확인 |

> ⚠️ 여기가 흔한 함정이다. 법령 본문이 아니라 **부칙**에 "이 법은 2026년 1월 1일부터 시행한다",
> "○○년 1월 1일 이후 발생하는 소득분부터 적용한다"가 붙는다. **부칙까지 확인해야 2026 귀속 기준이 맞다.**

## 1. 어디서 가져오는가

| 출처 | 용도 | 비고 |
|---|---|---|
| **국가법령정보센터** `law.go.kr` | 소득세법·조특법·국세기본법 **조문 원문** | 조문 단위로 끊겨 있어 우리 청킹 전략과 그대로 맞는다. 연혁법령에서 **2026 시행본** 선택 |
| 국세청 「금융소득 종합과세 해설」 (국세청 간행물) | 계산 예제·비교과세 설명 | 조문만으로는 계산 순서가 안 잡힌다 |
| 국세청 「세금절약 가이드」 / 국세상담센터 Q&A | 고객 언어로 된 설명 | 문서 08번(원천징수영수증)에 유용 |
| 홈택스 종합소득세 신고 도움말 | 신고 기한·가산세 실무 | 문서 06번 |
| 기획재정부 세법개정안 + 개정세법 해설 | **2025→2026 변경분** | 세율표·Gross-up율·ISA 한도가 바뀌었는지 여기서 확인 |

법령 원문은 조문 단위 인용이 가능하고 출처 표기가 명확해서, 우리 `DocumentMeta(doc, article, effectiveYear)`
구조와 궁합이 맞다. **블로그·세무사 사무소 글은 쓰지 않는다** — 출처로 인용할 수 없다.

## 1.5 파일 형식과 발췌 범위

### 결정: 원본은 PDF/DOCX로 받고, **인제스트 대상은 Markdown(`.md`)**

| 형식 | 인제스트 대상으로 | 이유 |
|---|---|---|
| **`.md`** | ✅ **채택** | 헤딩(`##`)이 곧 청크 경계다 — 우리 분할 전략이 이 구조에 의존한다 |
| `.pdf` | ❌ | 2단 조판·페이지 헤더/푸터·각주가 본문에 섞인다. **표가 깨진다** → 세율표가 깨지면 E11이 무의미 |
| `.docx` | △ | 구조는 있으나 POI 의존성 추가 + 표 손실은 여전. 중간 단계로만 |
| `.txt` | △ | 파싱은 쉽지만 헤딩이 없어 조문 경계를 못 잡는다 |

```
[수집]   PDF · DOCX  →  필요한 조문만 발췌  →  tax-docs/*.md  (git 커밋)
[런타임] IngestService 는 .md 만 읽는다.  원본 PDF 는 docs/raw/ 에 보관(인제스트 제외)
```

원본 PDF를 버리지 않고 `docs/raw/` 에 두는 이유는 **출처 추적** 때문이다.
"이 문장 어디서 왔냐"는 질문에 원본을 열어 보여줄 수 있어야 한다.

### 토큰은 문제가 아니다 — 정밀도가 문제다

먼저 통념을 하나 정정한다. **임베딩 비용은 무시할 수 있다.**
`text-embedding-3-small` 기준 소득세법 전문을 다 넣어도 몇 센트다. 잘라야 하는 진짜 이유는 셋이다.

| 이유 | 전체를 다 넣으면 |
|---|---|
| **검색 정밀도** | top-k=4 자리를 무관한 조문(근로소득·연금·사업소득)이 차지한다. 금융소득 질문에 §20(근로소득)이 딸려 나온다 |
| **프롬프트 토큰** | 인제스트가 아니라 **매 질의마다** 근거가 프롬프트에 실린다. 여기가 실제 비용 지점이다 |
| **출처 신뢰도** | 무관한 조문이 인용되면 답은 맞아도 출처가 틀린다 — 검증표상 실패다 |

### 실제 분량 — 걱정할 규모가 아니다

우리에게 필요한 것은 소득세법 200여 조문 중 **9개**다.

| | 조문 수 | 대략 분량 | 예상 청크 |
|---|---|---|---|
| 소득세법 | 9 | ~15,000자 | ~40 |
| 조세특례제한법 | 2 | ~5,000자 | ~13 |
| 국세기본법 | 3 | ~4,000자 | ~10 |
| 세무사법 | 2 | ~1,500자 | ~4 |
| 자체 작성 (08·09) | — | ~4,000자 | ~10 |
| **합계** | **16 조문** | **~30,000자** | **~77 청크** |

**전부 합쳐 3만자, 청크 80개 미만.** 이 정도는 top-k=4 검색이 충분히 정밀하게 동작하는 규모다.
문제는 "전체를 넣으면"이었고, 우리는 애초에 전체를 넣을 이유가 없다.

### 추가로 필요한 것 — 조문에 없는 것들

| 항목 | 어디서 | 왜 조문으로 안 되나 |
|---|---|---|
| ~~**누진공제액** 8구간~~ | — | ✅ 확보 · `taxdesk.brackets` 전건 일치 |
| ~~**Gross-up율**~~ | 소득세법 §17③ | ✅ **10%** 확인 (11% 아님) · `gross-up-rate=0.10` 수정 완료 |
| **비교과세 계산 예제** | 국세청 「금융소득 종합과세 해설」 | §62는 순서만 규정한다. 숫자 예제가 없으면 `steps[]` 를 검증할 수 없다 |
| **이자·배당소득** 원천징수영수증 서식 | 국세청 서식 | 08번 문서 |
| **근로소득** 원천징수영수증 서식 | 국세청 서식 | 08번 문서 · `prepaidTax`("결정세액" 칸)와 `otherIncome`("근로소득금액" 칸)을 짚어주기 위해 |

> 국세청 해설 간행물은 100페이지가 넘는다. **전부 필요 없다.**
> "금융소득 종합과세 세액 계산" 챕터(비교과세 예제가 있는 부분) **10~20페이지면 충분하다.**

### PDF에서 표를 옮길 때 ⚠️

**세율표는 복사하지 말고 눈으로 확인해서 옮긴다.** PDF 표는 복사하면 열이 섞이는 일이 잦고,
그 오류가 그대로 `taxdesk.brackets` 로 들어가면 **모든 세액이 틀린다.**
숫자 8×3 = 24개를 두 번 읽는 것이 가장 싼 검증이다.

### 법령 API는 보류

수집을 PDF/DOCX 수동으로 가는 이상 API는 쓰지 않는다.
다만 **조문 원문의 정확성**이 걱정되면 최종 대조용으로만 국가법령정보센터 원문을 열어 확인한다.
(API를 쓰더라도 런타임 의존은 안 된다 — 재현성이 깨지고 E11이 무의미해진다.)

## 2. 문서별 수집 명세

우선순위 ★는 **계산에 직결**되는 문서다. 이게 틀리면 세액이 틀린다.

### ★ 01 — 금융소득 종합과세 기준 `소득세법 §14 · §62`

| 확인할 것 | 코드와 맞물리는 값 |
|---|---|
| 종합과세 기준금액 (2,000만원 유지 여부) | `taxdesk.threshold-amount=20000000` |
| §14③11호 — 분리과세로 종결되는 요건 | 라우터 판정 문구 |
| §62 — 비교과세(종합과세 vs 분리과세) **계산 순서 원문** | `TaxCalcTools.calculateTax()` ①② |
| 기준금액을 "초과"인지 "이상"인지 | 경계값 테스트 (2,000만원 정확히면 분리과세) |

> §62 원문의 계산 순서를 그대로 옮겨야 한다. `steps[]`가 인용할 근거가 여기다.

### 02 — 이자소득의 범위 `소득세법 §16`

| 확인할 것 | 쓰임 |
|---|---|
| 이자소득 열거 항목 전체 | "예금 이자도 포함되나요?" 류 규정 질문 |
| 비영업대금의 이익 원천징수율(25%) | 예외 안내 |

### ★ 03 — 배당소득과 Gross-up `소득세법 §17 · §56`

| 확인할 것 | 코드와 맞물리는 값 |
|---|---|
| **배당가산율(Gross-up율)** — 11%인지 인하됐는지 **반드시 확인** | `taxdesk.gross-up-rate=0.11` |
| Gross-up 대상 요건 — **내국법인** 배당 + 법인세 과세된 소득 | `IncomeType.DOMESTIC_DIVIDEND` |
| 외국법인 배당이 제외되는 근거 조문 | `IncomeType.FOREIGN_DIVIDEND` |
| §56 배당세액공제 = 배당가산액 | 비교과세 ① |
| 기준금액 **초과분**에 대해서만 Gross-up 되는 근거 | `calculateTax()` |

> 이 문서가 가장 위험하다. Gross-up율과 대상 범위가 이 프로젝트에서 가장 틀리기 쉬운 부분이고,
> 실험 E11(문서↔설정 일치 검증)이 잡으려는 대상이기도 하다.

### ★ 04 — 종합소득세율과 누진공제 `소득세법 §55`

**8구간 세율표 전체를 원문 그대로.** 현재 `application.properties`에 들어 있는 값은
2024 기준 초안이므로 **2026 시행본으로 전건 대조**해야 한다.

| 과세표준 상한 | 세율 | 누진공제 | 현재 설정값 | 2026 확인 |
|---|---|---|---|---|
| 1,400만 | 6% | 0 | ✔ | ☐ |
| 5,000만 | 15% | 126만 | ✔ | ☐ |
| 8,800만 | 24% | 576만 | ✔ | ☐ |
| 1.5억 | 35% | 1,544만 | ✔ | ☐ |
| 3억 | 38% | 1,994만 | ✔ | ☐ |
| 5억 | 40% | 2,594만 | ✔ | ☐ |
| 10억 | 42% | 3,594만 | ✔ | ☐ |
| 초과 | 45% | 6,594만 | ✔ | ☐ |

> 누진공제액은 법령 본문에 없고 **누진세율 산식에서 유도**되는 값이다.
> 국세청 안내 표의 누진공제액을 쓰되, 구간·세율은 §55 원문으로 검증한다.
> 이 표가 `taxdesk.brackets[0..7]`과 **한 글자도 다르면 안 된다** — 실험 E11이 그걸 잡는다.

### 05 — 비과세·분리과세 상품 `조세특례제한법`

| 확인할 것 | 쓰임 |
|---|---|
| **ISA** 비과세 한도(일반형/서민형) — 확대 개정 여부 **확인 필요** | 시드 데이터, 금융소득 합계 제외 |
| ISA 초과분 분리과세율(9%) | 계산 예외 |
| 비과세종합저축 한도(5,000만원)·가입 요건·**일몰 기한 연장 여부** | 규정 답변 |
| 분리과세 신청 가능 상품 | "저는 안 걸리나요?" 답변 |

> 05번은 조특법이라 **일몰(적용 기한)이 있다.** 2026년에 아직 살아 있는 조항인지가 핵심 확인 사항이다.

### 06 — 신고·납부 기한과 가산세 `국세기본법 §47의2~4`

| 확인할 것 | 코드와 맞물리는 값 |
|---|---|
| 확정신고 기한 (2026 귀속 → **2027-05-31**) | `estimateDueDate(year)` |
| 성실신고확인 대상 기한 (6-30) | 예외 안내 |
| 무신고 가산세 (일반 20% / 부정 40%) | 가산세 안내 |
| 과소신고 가산세 (일반 10% / 부정 40%) | |
| **납부지연 가산세 이자율(1일 10만분의 ○○)** — 개정 잦음 | `estimateDueDate` 계산 |

### 07 — 거주자·비거주자 판정 `소득세법 §1의2`

| 확인할 것 | 쓰임 |
|---|---|
| 거주자 = 국내 주소 또는 **183일 이상** 거소 | 상담 전제 안내 |
| 비거주자의 금융소득 과세 방식(원천징수 종결) | 범위 밖 거절 근거 |

> 이 문서의 실제 역할은 **"우리 서비스는 거주자 기준으로 안내한다"는 전제를 명시**하는 것이다.
> 비거주자 질문은 `OUT_OF_SCOPE`로 보낸다.

### 08 — 원천징수영수증 읽는 법 `SKALA증권 자체 작성`

법령이 아니라 **우리가 쓰는 안내 문서**다. 다만 항목명은 실제 서식을 따라야 한다.

**이 문서의 역할이 바뀌었다.** 근로소득·타사 금융소득을 문서로 다루는 대신
**고객이 입력하는 파라미터**(`otherIncome` · `prepaidTax`)로 받기로 하면서,
08번은 *"그 숫자를 어느 칸에서 찾는지"* 를 알려주는 안내서가 됐다.
파라미터로 받으려면 고객이 자기 종이에서 그 숫자를 찾을 수 있어야 하므로,
이 문서는 없어진 게 아니라 **더 필요해졌다.**

| 확인할 것 | 쓰임 |
|---|---|
| **이자·배당소득** 원천징수영수증 서식의 실제 항목명 | 자사 발급분. 고객이 보는 종이와 용어 일치 |
| 소득구분코드 · 세율 · 기납부세액 표기 위치 | "여기 적힌 숫자가 뭔가요?" |
| 지방소득세 별도 표기(14% + 1.4% = 15.4%) | `Calculation.localTax` |
| **근로소득 원천징수영수증의 "결정세액" 칸 위치** | → `prepaidTax` 입력 안내 |
| 근로소득 영수증의 "총급여" vs "근로소득금액" 구분 | → `otherIncome` 입력 안내 (**혼동 지점**) |
| 타사 금융소득 영수증에서 소득금액·원천징수세액 칸 | → `externalAmount` · `prepaidTax` |

> ⚠️ **"총급여"와 "근로소득금액"을 고객이 헷갈린다.** 종합소득금액에 합산되는 것은
> 근로소득공제를 뺀 **근로소득금액**이다. 총급여를 입력받으면 세액이 과대 계산된다.
> 이 구분을 문서와 입력 안내에 명시하지 않으면 실무에서 가장 자주 나는 오류가 된다.

### 09 — 상담 범위 안내 `SKALA증권 자체 작성 · 근거 세무사법 §2`

**유일하게 우리가 100% 창작하는 문서**이고, 거절 응답의 출처가 된다.

| 담을 것 |
|---|
| 안내 가능: 자사 계좌 이자·배당, 종합과세 판정, 예상 세액, 신고 기한 |
| 안내 불가(업무 범위 밖): 양도·사업·부동산임대·퇴직소득 |
| 안내 불가(권한 밖): 타사 계좌 조회 → **금액을 알려주시면 합산** |
| 안내 불가(법적 제약): 신고 대리·세무 상담 — **세무사법 §2** 인용 |
| 고정 면책 문구 원문 |
| 세무사 상담 예약 안내 (승인 절차 포함) |

> 세무사법 §2(세무대리의 범위)와 §22(무자격자의 세무대리 금지) 조문을 확인해 인용한다.
> 거절에 **법 조문 출처가 붙는 것**이 이 프로젝트의 설계 포인트다.

## 3. 작성 형식 (9종 공통)

각 파일 상단 헤더는 이미 들어가 있다. 본문은 아래 3규칙을 지킨다 — 청킹과 출처가 여기 달려 있다.

```markdown
# 문서 제목

> 출처: 소득세법 §14 · §62
> 귀속연도: 2026
> 문서 성격: LAW

## 금융소득 2천만원 초과 판정          ← ① 헤딩을 조문 단위로 끊는다 (청크 경계)
소득세법 §14③11호 (2026 시행)          ← ② 헤딩 바로 아래 조문 번호를 재기입
                                          청크 하나만 봐도 출처가 완성되게
이자소득과 배당소득의 합계액이 2천만원을 ...
```

1. **헤딩(`##`)을 조문 단위로 끊는다** — 청크 분할이 이 경계를 따른다
2. **헤딩 바로 아래에 조문 번호를 다시 적는다** — 청크 하나만 봐도 출처가 완성되게
3. **수치는 `application.properties`의 `taxdesk.*`와 반드시 일치** — 실험 E11이 검증한다

추가 권장:
- 조문 원문 인용과 해설을 구분한다 (인용은 `>` 블록)
- 한 헤딩 = 300~500자. 너무 길면 하위 헤딩으로 쪼갠다
- 계산 예제는 **숫자를 명시**한다. 문서 예제와 `TaxCalcTools` 결과가 일치하는지가 골든셋 항목이 된다
